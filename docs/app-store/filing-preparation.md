## 当前缺口与办理顺序

1. 选定支持北京个人 APP 备案的实际接入服务商，先确认所购静态托管产品能提供备案服务，再购买域名和服务。仅有对象存储、CDN 或 GitHub Pages 访问地址，不足以推定具备备案资格。
2. 用主办者本人身份注册并实名核验域名。当前 `lmjian.github.io` 是 GitHub 分配的子域名，不是本人实名注册的域名；不能编造域名所有权。本轮未购买域名、服务器或提交备案。
3. 通过接入商准备北京个人主体资料、服务负责人信息、真实性核验及实际域名/IP 接入信息。身份证、详细地址和核验照片直接在服务商官方平台提交，不进入 Git 或聊天记录。
4. 正式 Apple 开发者身份确定后，确认发行 Bundle ID、证书公钥和指纹。保持现有应用升级身份与 App Group；若未来正式身份必须变更，先评估数据迁移，不直接重命名现有 App。
5. 按接入商系统提交 APP 备案，完成其核验和主管部门审核。获批后才能填写真实备案号，补上 App 内可见的备案信息与查询链接，并在 App Store Connect 填写对应信息。

工信部要求通过接入服务商或分发平台向住所所在地省级通信管理局办理；材料齐全准确后的审核时限不等于整体办理周期，也不代表自动获批。[工信部通知](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2023/art_dd783a581c9644a4aee10afa582811db.html)。

北京个人备案的接入商公开规则要求主体与域名持有者一致，并有证件有效期、负责人年龄等条件；网站与 APP 表单有所区别，按实际 APP 流程核验，不能套用网站名称字段代替 APP 字段。[北京规则](https://help.aliyun.com/zh/icp-filing/icp-filing-regulations-for-beijing/)、[个人 APP 流程](https://help.aliyun.com/zh/icp-filing/basic-icp-service/getting-started/quick-sta-rt-for-icp-filing-for-personal-app)。

## 静态文件迁移方案

业务继续采用“客户端 + 静态 JSON”，不需新增业务 API 服务。正式域名确定后，把相同 index 与不可变年度文件部署到有备案资格的静态托管；验证 HTTPS、同源、大小、SHA-256 与年份后，再更新 App 的入口。保留旧 GitHub Pages 入口供已安装版本使用，不改博客导航或文章。先发布文件再切换客户端，下载失败保持最后有效缓存；不降低校验来掩盖网络问题。

隐私、支持和介绍页面可使用同一正式静态站点；变更托管方后更新 App 内与公开隐私说明，并重新核对网络日志及隐私问卷。仅给 GitHub Pages 绑定自有域名不会自动产生中国大陆备案资质。
